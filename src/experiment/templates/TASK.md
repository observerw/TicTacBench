# Timing Closure Task

## Task Description

Your task is to optimize the suboptimal RTL design `suboptimal.v` to **achieve post-PnR timing closure**.

In workspace, you will find the following files (DO NOT EDIT):

- `sta/` contains STA-related files, including:
  ```
  sta/
  ├── config.default.json # LibreLane configuration for final post PnR STA. DO NOT EDIT
  ├── pnr.sdc # Timing constraint file used by the flow. DO NOT EDIT
  ├── librelane-sta/<module>/Post # Full LibreLane post-PnR run artifacts and detailed reports
  ├── librelane-sta/<module>/Post/metrics.json # QoR/STA metrics of the design
  ```
- `suboptimal.v` is the original RTL code that needs to be optimized. DO NOT EDIT this file directly; all your optimizations should be implemented in `optimized.v`.

## Task Requirements

- **The optimized code should be `optimized.v`**:
  - **It must contain a `module <module>_optimized()` module**, with the module definition kept exactly the same as the original code; no modifications to the module ports are allowed.
  - **All optimizations must be implemented at the RTL level**; hand-written netlists, gate-level manual rewrites, or other non-RTL replacement methods are not allowed.
  - The optimized code must be **synthesizable and functionally equivalent** to the unoptimized version.
  - **DO NOT use pipeling/latency-changing to improve timing unless explicitly asked to**, otherwise your design will fail equivalence checking.
  - After exploring multiple optimization iterations and STA results when needed, **the final `optimized.v` must contain the best overall solution you found**, rather than an earlier intermediate candidate.
- **Run the given tools to verify/analyze your code**. Strictly follow the tool instructions. DO NOT try to run commands manually.

## Finish Your Run

After the task is complete, **you must call the `finish` tool to end the run**. DO NOT stop before calling `finish`, or the run will be considered incomplete and fail acceptance.

A `finish` call requests acceptance. It will look for `optimized.v` and check its validity. If the subsequent compile or equivalence check fails, you must continue revising `optimized.v` based on the failure feedback until it passes or the run stops.

## Acceptance Criteria

The final acceptance will conduct the full post-PnR flow. The evaluation considers the following aspects:

- Timing Convergence: Whether the timing closure target is achieved
- WNS Improvement: The degree of improvement in Worst Negative Setup Slack
- Violation Count: The number of remaining setup timing violations
- Area and Power: The magnitude of area and power changes introduced by the optimization

The optimization should aim to **minimize the physical modification overhead** while **reducing the number of violations and lowering WNS**, ultimately achieving timing closure. 

It is forbidden to trade timing improvement for excessive area or power increase.

Make a strong best-effort optimization attempt to achieve timing closure and the best overall optimization result; do not stop at the first plausible solution.
